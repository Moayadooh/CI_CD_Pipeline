
Step 1
Install Jenkins

Install Java Development Kit (JDK) in the Windows server:
https://adoptium.net/

Verify after instllation:
java -version

Install Jenkins in the Windows server:
https://www.jenkins.io/download/

Run service as local or domain user and enter your Windows username and password

Set default to 8080 and click Test Port to verify it is available

Point the Java Home Directory JDK installation path (e.g., C:\Program Files\Eclipse Adoptium\jdk-17...)

Verify after instllation:
Win + R, type services.msc and verify Jenkins service status Running

Open Jenkins in browser:
http://localhost:8080

Create the primary Admin account (username, password, email)

to access the Jenkins from local environment go to the Windows server and open Windows Defender Firewall with Advanced Security and create an Inbound Rule to allow TCP traffic on port 8080

Step 2
Install Project Dependencies

Install .NET 10 SDK on the Windows server:
https://dotnet.microsoft.com/en-us/download/dotnet/10.0

Verify after instllation:
dotnet --version

Restart the Jenkins Windows Service

Test .NET 10 Detection in a Pipeline by Create a Pipeline job:
pipeline {
    agent any
    stages {
        stage('Check .NET Version') {
            steps {
                bat 'dotnet --info'
            }
        }
    }
}

Step 3
Configure Jinkinsfile & CI/CD Pipeline

Create a file named Jenkinsfile to the root of .NET10 web app repository
pipeline {
    agent any

    environment {
        // Adjust these to match your project's structure
        PROJECT_PATH = 'src/MyWebApp/MyWebApp.csproj'
        TEST_PATH = 'tests/MyWebApp.Tests/MyWebApp.Tests.csproj'
        PUBLISH_DIR = 'publish_output'
    }

    stages {
        stage('Restore') {
            steps {
                echo 'Restoring NuGet packages...'
                bat "dotnet restore ${PROJECT_PATH}"
            }
        }

        stage('Build') {
            steps {
                echo 'Building the .NET 10 app...'
                bat "dotnet build ${PROJECT_PATH} --configuration Release --no-restore"
            }
        }

        stage('Test') {
            steps {
                echo 'Running Unit Tests...'
                bat "dotnet test ${TEST_PATH} --configuration Release --no-build"
            }
        }

        stage('Publish') {
            steps {
                echo 'Publishing the application...'
                bat "dotnet publish ${PROJECT_PATH} --configuration Release --no-build --output ${PUBLISH_DIR}"
            }
        }

        stage('Archive Artifacts') {
            steps {
                // Saves the compiled output in Jenkins for download or later deployment
                archiveArtifacts artifacts: "${PUBLISH_DIR}/**/*", fingerprint: true
            }
        }

        stage('Deploy') {
            steps {
                echo 'Artifacts are ready. Deployment logic goes here.'
                // Example: Copy files to a server, build a Docker image, etc.
            }
        }
    }

    post {
        always {
            cleanWs() // Clean up the workspace after the build to save disk space
        }
        success {
            echo 'Pipeline completed successfully!'
        }
        failure {
            echo 'Pipeline failed. Check the Jenkins console output.'
        }
    }
}

Create the Jenkins Pipeline Job:
1. Open the Jenkins dashboard and click New Item.
2. Enter a name for your project, select Pipeline, and click OK.
3. Scroll down to the Pipeline section.
4. Change the Definition dropdown to Pipeline script from SCM.
5. Select Git as the SCM, provide your repository URL, and attach your Git credentials if it is a private repository.
6. Ensure the Script Path is exactly Jenkinsfile.
7. Save the configuration.

Configure Webhooks to Automate builds on push:
To make the pipeline run automatically, set up a webhook in your Git provider (GitHub, GitLab, Bitbucket) pointing to http://<your-jenkins-server>/github-webhook/. In your Jenkins job configuration, under Build Triggers, check the box for GitHub hook trigger for GITScm polling (or your provider's equivalent).
